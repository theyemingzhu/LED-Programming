## Defects

**F16 · fixed on branch** · Lights off while Studio says Connected. Screen: Patterns, footer Connected, Tune Brightness 100%. Expected: the strip plays the selected look. Observed: strip dark. Root cause: card zone reports blackout true (a Stop sent earlier); Studio surfaces blackout only inside CardControlDrawer, never on Patterns or Card Home. Confirmed by Adrian: tapping a pattern on the card's own page lit the strip. Fixed on the branch (commit "fix: F16 - surface a card-side blackout and make Recover lights the primary action"): the shared journey evidence reads /api/zones, Card Home and Patterns show "Lights are off on the card." with Recover lights as the one action, gated off provisional and not-ready cards. Regression [J16-blackout] in tests/journey-continuity.spec.ts; conductor re-ran: journey 10/0, unit 2392/2392, mutation (blackout fact stubbed false) turns J16 red.

**F17 · fixed on branch** · Pattern clicks in Studio never reach the card; toast "The card page opened but did not answer". Screen: Patterns. Expected: strip changes on click. Observed: pop-up card window opens, Studio times out after 10 s. Root cause (proven in a real browser against the real card): Studio reopens the pop-up by window name with a URL whose only variable part is the fragment, so an already-open pop-up is focused, never re-executed, and never re-posts ready; Studio then wipes its own verified bridge state and waits. The halfway nudge meant to re-navigate the window was gated on a reservation that no code ever set. Excluded with evidence: origin mismatch, 512-char fragment cap, allowed-keys rejection, version gating. Fixed on the branch (commit "fix: F17 - reopen the card bridge with a fresh URL so a reused pop-up answers again"): a per-attempt token in the query string; unit 2390/2390; test:core green; mutation (token back in the fragment) turns 3 tests red. Regression: src/lib/cardBridge.openLocalCardPage.test.js.

**F18 · fixed on branch** · Edit in Studio from the card pop-up opens a new Studio tab at Setup phase 1 ("wiring has changed in Studio since it was installed", primary "Use this card's project") instead of returning to the open Studio tab on Patterns. Screen: card pop-up, then new Studio tab at ?cardBridge=1&cardHost=lightweaver.local&editLook=combo-aurora#screen=card&section=overview with "Restored from recovery copy". Expected: back in the existing Studio tab, Patterns, Aurora selected. Root cause: firmware 1548's Edit in Studio navigates the opener Studio tab to a new URL (a full reload), so in-memory state is lost and the autosaved copy is restored; that copy carries the owner's unsaved wiring edit, so the resolved-adoption run honestly refuses and the phase-1 ladder is the only screen left. The intent then reached Patterns, which bounced back to the card screen when it could not claim the exact-fingerprint edit authorization. Fixed on the branch (commit "fix: F18 - an edit request from the card page lands on Patterns and stays there, never the setup ladder"): Card Home routes a same-project edit intent to Patterns after the adoption refusal; Patterns stays put and shows its own "Verify project in Card status" step; the look is offered, not auto-selected (write gates untouched). Regression tests/journey-edit-intent.spec.ts [J18-edit-intent] and [J18-bare]; conductor re-ran 2/0. Firmware half (message the open Studio tab instead of reloading it) waits on Adrian's release call.

**F19 · split: F17-A queued, firmware part pending Adrian's release call** · The pop-up exists at all in Chrome, and opens too small to show its content. Root cause, part 1 (Studio): Patterns forces the bridge whenever the page is https (lw-pattern.jsx needsBridge / preferBridge; cardConnection.js canPushDirectlyToCard returns false on https). Measured from the live Studio origin: direct GET and a POST preflight to the card both succeed with private-network CORS, so the premise is false. CardControlDrawer already does not force the bridge. Part 2 (firmware skew): the page firmware 1548 serves lacks the bridge-utility element that the current source has, so the compact utility view fails and the full card page renders inside a 360x180 window; fixed in firmware source, needs a signed release and a flash. Studio part fixed on the branch (commit "fix: F17-A - Patterns reaches the card directly on https and opens the pop-up only when the direct probe fails"): Patterns probes connectCardTransport first and opens the pop-up only when the probe fails; regression tests/journey-direct-preview.spec.ts [J17-direct] and [J17-direct-fallback]; conductor re-ran 2/0, mutation (helper forced to bridge) turns J17-direct red.
