# Lightweaver function preservation audit

November 17, 2026

## Verdict

The desktop mock simplifies away working controls. It showed the shape of a workflow and omitted the complete editor and many conditional states. It cannot establish functional equivalence. Keep the current working Layout, rail and footer as the reference for implementation. In the next design pass, a control can move once its destination, purpose, and behavior have been demonstrated.

Public Studio reported build 2424 at revision `39a72bebe85606b5029f5156378da3e17a0496fd`. The local capture uses the source of draft PR #427 at `9166537816bcab962ed3c7f09c5634664f4c2de0`, which changes the Looks editor, its previews and display order. Layout and the global shell are untouched by that PR. The offline render uses a two-ring project and simulated browser actions. The side-mirror tests use a larger multi-strip fixture. Physical lights, installed playback and firmware outcomes require card evidence.

## Working rule for the next design pass

- Keep the desktop canvas and direct task controls from the working baseline. The first structural change should give the inspector explicit **Artwork**, **Connections**, and **Sides** destinations while retaining selected-strip edit controls and a direct path back.
- Longer, less frequented operations such as advanced mapping and build reference can use ordinary screens with stable back navigation. Render the actual contents before approving their replacement. Keep the relevant evidence, safety checks and returned selection in scope.
- Keep the live Card action, short-strip test, version and update controls within reach when changing sidebar or footer. Use the existing state machine as the starting point, and test each state after a move.
- Define any intended behavioral change in its own acceptance case. Existing UI placement may change. Scope, data, permissions, target identity, reversibility, preview/installed distinction and physical semantics remain specific checks.
- Show equivalent content and state on desktop and phone. Run the existing targeted suites against a working implementation and check any new navigation with the relevant simulator. Preserve physical acceptance as its own proof where LEDs, wiring or card writes are involved.
