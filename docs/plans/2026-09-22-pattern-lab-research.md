# Pattern Lab authoring, persistence, and handoff audit

## Finding in one sentence

Pattern Lab is a real recipe editor with browser recovery, named private drafts, a tested round trip through **Patterns**, native Color Journey compilation, and a separate deterministic `.lwseq` bake path; it is **not integrated with Show**, and “Standalone ready” means the recipe compiles against the Studio's built-in ESP32-S3 descriptor, not that a connected card has received or played it.

## The tangible owner workflow that exists today

1. Open **Lab**. On first load it consumes a one-shot Patterns-to-Lab handoff, otherwise recovers the project's unsaved Lab working copy, otherwise follows `#patternId`, and finally starts with “Amber violet drift.” The working recipe, source recipe, and preview time are continuously stored per project in browser storage. 2. The visible workflow is **Choose → Edit → Evolve → Add to Patterns**. The owner chooses a built-in pattern or one of five procedural generators, renames it directly above the preview, adjusts contextual controls, optionally builds a 5–15 minute evolution or Color Journey, and previews the mapped piece or physical strip order. ## Round-trip fidelity and limits

- Linked native looks retain recipe ID, seed, palette, provenance, exact default/section look values, saved-look ID, and playlist identity across Patterns → Lab → Patterns and reload. This is browser/project persistence evidence, not physical output evidence. [pattern-lab-look-roundtrip.spec.ts:63](../../lightweaver/tests/pattern-lab-look-roundtrip.spec.ts#L63)
- A new native Lab design becomes a selected Patterns look and reopens as the same editable linked look after reload. Studio-only recipes also reopen, while default card state and patch board remain unchanged. [pattern-lab-look-roundtrip.spec.ts:121](../../lightweaver/tests/pattern-lab-look-roundtrip.spec.ts#L121) [pattern-lab-look-roundtrip.spec.ts:152](../../lightweaver/tests/pattern-lab-look-roundtrip.spec.ts#L152)
- When a Patterns look has linked recipe metadata, Lab prefers it. Patterns-side color/brightness/speed changes are merged back only when they differ from the linked source; a changed underlying pattern falls back to reconstructing a plain built-in recipe. [patternLabFromLook.js:13](../../lightweaver/src/lib/patternLabFromLook.js#L13)
- Native handoff preserves the whole editable recipe in the project, but the card look itself is a reduced visual projection: pattern, brightness, speed, hue/saturation fields. The Lab **Movement** macro affects the Studio preview geometry but is absent from the native visual-look conversion. [patternLabLookColor.js:6](../../lightweaver/src/lib/patternLabLookColor.js#L6) [patternLabPatternAdapter.js:208](../../lightweaver/src/lib/patternLabPatternAdapter.js#L208)
- Baked sequence metadata survives project serialization, but the binary is only in the downloaded controller package. It is not an editable/reopenable Patterns look; its embedded manifest recipe is provenance, not a wired UI reopen path. [patternLabHandoff.js:389](../../lightweaver/src/lib/patternLabHandoff.js#L389) [patternLabHandoff.js:658](../../lightweaver/src/lib/patternLabHandoff.js#L658)
- Private-draft reopen resets preview time to zero even though crash/reload recovery retains preview time. There is one-level undo for pattern replacement/open/delete/replace, not a slider history. ## Pattern Lab and Show are separate products today

Show never reads `standaloneController.looks`, `patternLabRecipe`, or Pattern Lab drafts. It selects one of nine `mandalaEngine` modes or an area/voice composition, derives live audio features, paints its own frame, and optionally sends raw frames through the card frame stream. [lw-show.jsx:1](../../lightweaver/src/v3/lw-show.jsx#L1) [lw-show.jsx:323](../../lightweaver/src/v3/lw-show.jsx#L323) [lw-show.jsx:440](../../lightweaver/src/v3/lw-show.jsx#L440) [lw-show.jsx:501](../../lightweaver/src/v3/lw-show.jsx#L501)

The only shared concepts are project geometry, card authority, and the physical frame transport. There is no **Use in Show**, no saved-Lab-design picker in Show, no conversion from a recipe to a Show voice/ground, and no Show-to-Lab round trip. **Play on the lights** streams Show's current audio-reactive frame and intentionally writes no persistent card mode. ## Source evidence versus runtime proof

- **Source evidence:** all workflow and limits above were traced through the current React screens and library code, rather than plans/docs.
- **Automated runtime proof reported for this audit:** 50 focused unit checks plus 12 browser checks covering Color Journey standalone behavior and Lab/Patterns look round trips passed. The round-trip browser test explicitly blocks card networking and says it never proves physical card output. [pattern-lab-look-roundtrip.spec.ts:63](../../lightweaver/tests/pattern-lab-look-roundtrip.spec.ts#L63)
- **Visual runtime proof reported for this audit:** the actual Lab fixture was inspected. While disconnected it displayed **Standalone ready**. That confirms the UI behavior and exposes the distinction below; it does not prove install or playback.
- **No hardware proof:** no card was called, configured, flashed, or observed. Native compilation, package construction, direct install code, firmware sequence playback, and Show streaming are source/test evidence only in this note.

## Five high-value gaps

1. **There is no Pattern Lab → Show workflow.** A tangible integrated experience needs an explicit contract: choose a Lab recipe as Show ground/voice/material, define which recipe controls audio may modulate, preview the exact composition, and retain an editable reference. Today Show has a parallel mode/voice model and parallel storage.
2. **The bake path stops at downloads and hidden diagnostics plumbing.** Primary **Add to Patterns** turns bakeable recipes into Studio-only project looks; the owner must discover **Card compatibility & diagnostics**, bake, review, add, then handle a downloaded standalone package. Patterns' ordinary **Install on card** does not consume `sequenceAssets`. This is the largest gap in “load this specific design onto my card.”
3. **“Standalone ready / Live on card” overstates current evidence.** PatternLabScreen does not pass a connected-card descriptor into classification; it uses the built-in default descriptor, while the export copy says “connected card descriptor.” The observed disconnected fixture still showed **Standalone ready**. Rename this to “Card format ready” until exact-card evidence is present, or wire current firmware capabilities into the verdict. [PatternLabScreen.jsx:952](../../lightweaver/src/pattern-lab/PatternLabScreen.jsx#L952) [patternLabCompatibility.js:40](../../lightweaver/src/lib/patternLabCompatibility.js#L40) [PatternLabExport.jsx:7](../../lightweaver/src/pattern-lab/PatternLabExport.jsx#L7)
4. **A native-looking preview can author movement that the native handoff drops.** Built-in patterns expose **Movement** and the Studio renderer applies it to strip geometry, but the native card look projection only includes color, brightness, speed, and existing card modifiers. Either classify movement-edited recipes as bake-only, compile the macro to a firmware-supported parameter, or remove/label the control for native output.
5. **Bake limits disagree across boundaries.** The worker/baker hard-stop at 1024 source pixels and size the absolute file budget from that cap, while handoff manifest validation accepts up to 4096 pixels and tests discuss longer card outputs. Reconcile source pixels, physical output pixels, hardware max, manifest max, and UI compatibility budgets so a recipe cannot be advertised bakeable and then fail at bake time. [patternLabWorkerProtocol.js:16](../../lightweaver/src/lib/patternLabWorkerProtocol.js#L16) [lwseqBake.js:45](../../lightweaver/src/lib/lwseqBake.js#L45) [lwseqBake.js:323](../../lightweaver/src/lib/lwseqBake.js#L323) [patternLabHandoff.js:166](../../lightweaver/src/lib/patternLabHandoff.js#L166)

One smaller correctness defect surfaced during the audit: `deleteDraft()` executes `void remaining` after completing the delete/undo setup, but `remaining` is undefined, so the caught `ReferenceError` can overwrite the success message with a failure even though deletion occurred. [PatternLabScreen.jsx:1630](../../lightweaver/src/pattern-lab/PatternLabScreen.jsx#L1630)
